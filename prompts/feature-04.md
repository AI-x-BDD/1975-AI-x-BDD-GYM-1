# Feature 04：刪除任務 — 原始 Prompt

請依序啟用以下三支 Skills：

/double-diamond-principle
/git-conventional-commit
/trunk-based-development

接著請幫我開發 Mini Issue Tracker 的第四個功能：**刪除任務（Delete Task）**。

### 功能需求
1. 每筆任務提供「刪除」按鈕。
2. 使用者點擊刪除按鈕後，必須顯示確認對話框，避免誤刪。
3. 確認對話框應清楚指出即將刪除的任務。
4. 使用者確認後，依據任務 ID 刪除指定任務。
5. 使用者取消時，不得修改任何任務資料。
6. 刪除成功後，任務清單立即更新。
7. 刪除其中一筆任務，不得影響其他任務。
8. 刪除最後一筆任務後，顯示「目前沒有任務」。
9. 沿用現有任務資料模型與記憶體狀態管理，不加入 localStorage。
10. 本次採用永久刪除，不實作垃圾桶、復原或軟刪除功能。

### 開發要求
1. 運用 Double Diamond，簡要完成 Discover、Define、Develop、Deliver，釐清刪除需求、誤刪風險及驗收條件。
2. 比較適當的確認方式，例如瀏覽器原生確認對話框與自訂確認視窗，依照目前專案架構選擇較簡單且合理的方案。
3. 遵守 Trunk-Based Development，將變更控制在必要範圍，確保主幹維持可運作。
4. 不破壞前面三個功能：新增任務、顯示任務清單、編輯任務。
5. 補上必要的自動化測試，至少包含：
   - 確認後成功刪除指定任務
   - 取消刪除後資料不變
   - 刪除一筆任務不影響其他任務
   - 刪除最後一筆任務後顯示空清單
   - 使用任務 ID 正確識別刪除目標
6. 實際執行測試與建置，回報真實結果。
7. 遵循 Conventional Commits，依照變更目的建立合理的 Commit。
8. 不擅自推送遠端、改寫 Git 歷史或修改無關功能。
9. 將本次開發及觀察資料記錄於 `docs/observations/feature-04.md`。

### 完成後請回報
- Double Diamond 四階段摘要
- 本次實作內容與設計決策
- 測試案例及實際測試結果
- Git Branch 與整合狀態
- Commit Message 與 Hash
- 三支 Skills 的實際遵循證據
- 遇到的問題及優化空間

請只完成第四個功能，不要提前實作任務狀態切換、搜尋、篩選或資料持久化。
